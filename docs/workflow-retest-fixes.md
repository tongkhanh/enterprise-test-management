# Workflow retest fixes

Branch: `fix/workflow-retest-findings`, based on main `3e7ed7c`.

## Changes

- Execution cards display persisted `actualResult` notes and allow editing or clearing them without selecting the verdict again. Runner evidence and QA verdict remain separate.
- Feature Test Plans have an explicit **Lưu nháp** action in the editor and preview. Saved drafts can be reopened and updated in place, then submitted through the existing QA approval flow. Submission revalidates source stories and document completeness. No runtime Environment is required to save a document draft.
- Generic PDF exports use an installed Unicode font, full-width label/value blocks, and page-aware wrapping. Compose and CI install DejaVu; Windows can use Arial, and `PDF_FONT_PATH` remains supported.
- During AI quota/overload failures, User Story and Test Plan drafts retain source criteria. Test Case fallback copies one approved acceptance criterion per marked source draft instead of adding unrelated permission/alternate scenarios. These drafts need human refinement and do not contain inferred locators.
- The quality badge warns about marked source drafts and legacy placeholder test data. It remains a completeness check, not proof that a business scenario or automation is correct.
- The Test Case editor exposes structured test data as a validated JSON object and per-step test data. This preserves existing structured values unless explicitly changed; exports continue masking sensitive fields.
- Single-case and combined exports resolve the current Ready runtime URL without rewriting the approved specification. A bound unavailable environment never falls back to an obsolete URL.
- Script generation identifies quota/overload failures explicitly; incomplete scripts still cannot validate or execute as automation.
- Starting a new scope inserts it into the query cache before selection, avoiding a missing-profile window. A missing profile produces an actionable save error rather than an undefined-ID exception.

## Retest

1. Reopen the completed run: both saved QA notes should be visible. Edit a note, save and refresh; repeat in Manual and Auto modes.
2. Create a Feature Test Plan draft, click **Lưu nháp**, refresh, reopen the saved draft and edit it. Submit it and verify there is one record with PendingApproval, then review through QA.
3. Export an approved report to PDF: verify Vietnamese headings, long notes and page breaks. Export Test Cases after binding a Ready URL and verify the Target URL column.
4. Review fallback-generated drafts: confirm source acceptance criteria are retained, no unsupported scenarios are added, and incomplete drafts are visibly marked for review.
5. Edit structured and per-step test data, save/reopen, then check the workbook's Test Data and Steps sheets.

## Remaining limits and audit work

- Gemini availability/quota remains external. Executable script generation with a working provider still needs a live workflow retest; source drafts are not automatically executable scripts.
- Existing reviewed documents and exported reports are not migrated or regenerated by these changes.
- Automatic Board movement to Done is not introduced; the team still needs to agree on its relationship to executions and QA overrides.
- Report Manual/Auto breakdown, zero duration values, and the failure/evidence/RCA/Issue workflow need separate investigation.
- The reported new-scope popup was not captured exactly; the missing-profile guard addresses a source-level race, but that popup still needs a UI retest.
